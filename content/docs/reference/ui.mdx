### `ui.IsKeyDown(key)` [#ui-iskeydown]

True while the key is held down, as the game's own input reports it for the local player. It takes the key names [`ui.Hotkey`](/docs/reference/ui#ui-hotkey) takes. A name with Ctrl, Shift or Alt ("Ctrl+K") is true only while the key is down with exactly those held; a plain name is true whatever else is held. It is false while the game has no local player, and for a name the game does not know. It does not look at whether the menu is open or a text box has the keyboard (see [`ui.IsTyping`](/docs/reference/ui#ui-istyping)). Every call asks the game, so use it in a loop that runs while something is held, such as one a [`ui.Hotkey`](/docs/reference/ui#ui-hotkey) started, and not in every frame of the game. It raises an error for a key that is not text, for empty text, and for a word before the key that is not Ctrl, Shift or Alt.

```lua
ui.IsKeyDown(key: string): boolean
```

| Parameter | Type | Description |
| --- | --- | --- |
| `key` | `string` | An engine key name such as "A", "LeftShift" or "MiddleMouseButton". |

**Returns** `boolean`

## WaxWindow [#waxwindow]

A window in the menu. Controls added to it go into its body, or into a first page called "Main" when it has pages. The player moves it by its title bar and resizes it by any edge or corner; the bottom right corner shows a grip. Resizing stops at the window's minimum size and at the edges of the screen. A mod's windows come up together, with that mod's key (see ui.Keys), and other mods' windows stay as they are.

It can also do everything [`WaxContainer`](/docs/reference/controls#waxcontainer) can. You get one from [`ui.Debug.Window`](/docs/reference/ui#ui-debug-window), [`ui.Window`](/docs/reference/ui#ui-window), [`ui.Windows`](/docs/reference/ui#ui-windows). Below, `window` stands for one of these.

## WaxModel [#waxmodel]

A creature or any other skeletal mesh of the game, drawn in 3D. It turns slowly by itself until the player touches it. The model follows the mouse when dragged: to the right its near side goes right, and down it is seen more from above. The wheel moves the camera nearer and further while the mouse is over the view, and the page does not scroll then. Two presses in a row put the view back. Nothing is drawn while the view is not on screen.

It can also do everything [`WaxControl`](/docs/reference/controls#waxcontrol) can. You get one from [`container:Model`](/docs/reference/controls#container-model). Below, `model` stands for one of these.
