A **signal** is an event you can listen to. You connect a function to it. Each time the event happens, your
function runs.

```lua title="init.lua"
game.MapChanged:Connect(function(name)
    ui.Notify("You are now on " .. name, { title = "Map changed" })
end)
```

When the event happens, the signal **fires**. `game.MapChanged` fires when the world changes, and it gives your
function the new map's name.

## Signals that Wax gives you

| Signal | Fires when | Your function gets |
| --- | --- | --- |
| `game.MapChanged` | The world changes. | The new map's name. |
| `ui.Opened` | The menu opens. | Nothing. |
| `ui.Closed` | The menu closes. | Nothing. |
| `ui.Keys.Changed` | The key of somebody's windows changes. Not in Wax 0.2.1. | The owner (`"Wax"` or a mod's id) and the new key. |
| `ui.KeyChanged` | The key of the Wax panel changes. | The new key. |
| `ui.ThemeChanged` | The theme changes. | The theme's name. |
| `ui.ScreenChanged` | The game's window or the interface size has a new size and has stopped changing. | The new width and height, as `ui.ScreenSize()` gives them. |
| `ui.GameScreenChanged` | The game shows another of its own screens, another tab of its menu, or none any more. Not in Wax 0.2.1. | The screen's name and tab, as `ui.GameScreen()` gives them. |
| `window.Opened`, `window.Closed` | A window is shown or hidden. | Nothing. |
| `window.PageChanged` | Another page of a window is chosen. | The page's name. |
| `panel.Resized` | A [panel](/docs/gui/overlays#panels) made with a `place` function got another size. Not in Wax 0.2.1. | Its new width and height. |
| `panel.Scrolled` | The mouse wheel was turned over a panel. | `1` for down, `-1` for up. |
| `control.Changed` | The user changes a control. | The new value. |

Controls have a few more. Each one is listed with its control on the [Controls](/docs/gui/controls) page.

The world has signals too, from the next version of Wax on: for [your character](/docs/character#signals),
[hits, deaths and items](/docs/events), [the time and the weather](/docs/time-and-weather), and for
[any value you want to watch](/docs/watching). [Creatures](/docs/creatures#when-creatures-come-and-go) have
theirs already.

### Follow the size of the screen

`ui.ScreenSize()` gives the size of the screen in the units windows and panels are laid out in. It changes
when the player resizes the game's window or picks another interface size. `ui.ScreenChanged` fires once
with the new size, after the change has stopped for a moment. It does not fire while the window is still
being dragged.

```lua title="init.lua"
local window = ui.Window({ title = "Screen", width = 300, height = 120 })
local size = window:Field("Screen", "")

local function show(width, height)
    size:Set(("%.0f by %.0f"):format(width, height))
end

show(ui.ScreenSize())
ui.ScreenChanged:Connect(show)
```

While the game is starting it has no screen yet. `ui.ScreenSize()` then answers 1920 by 1080, and
`ui.ScreenChanged` fires if the real size turns out to be another one. A mod that works out a layout from the
screen when it loads should listen to `ui.ScreenChanged`, so that it is right after a start of the game too.

A mod whose whole layout depends on the screen can also load itself again. `mod.Reload()` does that at the
start of the next frame, the way saving a file does:

```lua title="init.lua"
ui.ScreenChanged:Connect(function()
    mod.Reload()
end)
```

## Stop listening

`Connect` gives back a **connection**. Call `Disconnect` on it to stop.

```lua title="init.lua"
local connection = ui.Opened:Connect(function()
    print("The menu opened.")
end)

local window = ui.Window({ title = "Signals" })
window:Button("Stop printing", function()
    connection:Disconnect()
    print("Still connected:", connection.Connected)   -- false
end)
```

When your mod reloads, Wax disconnects everything the mod connected. You only need `Disconnect` to stop
before that.

## Only once

`Once` is like `Connect`, but your function runs for the next fire only.

```lua title="init.lua"
ui.Opened:Once(function()
    ui.Notify("You opened the menu for the first time since this mod loaded.")
end)
```

## Wait for a signal

Inside a [task](/docs/tasks), `Wait` pauses until the signal fires. It gives back what the signal sent.

```lua title="init.lua"
task.spawn(function()
    print("Waiting for a map change...")
    local name = game.MapChanged:Wait()
    print("The map is now", name)
end)
```

## Make your own signal

`Signal.new` makes a signal. `Fire` fires it. Whatever you pass to `Fire` reaches every connected function.

```lua title="init.lua"
local scored = Signal.new("scored")

scored:Connect(function(points)
    print("Scored", points)
end)

scored:Once(function()
    print("First score!")
end)

scored:Fire(10)
scored:Fire(5)
```

The log shows:

```text
First score!
Scored 10
Scored 5
```

The newest connection runs first. That is why `First score!` comes before `Scored 10`.

Use your own signals to keep the parts of a mod apart. One file fires `scored`. Another file listens and
updates the window. Neither has to know how the other works.

## The functions

| Function | What it does |
| --- | --- |
| `Signal.new(name)` | Makes a signal. The name shows up in error messages. |
| `signal:Connect(fn)` | Runs `fn` on every fire. Gives back a connection. |
| `signal:Once(fn)` | Runs `fn` on the next fire only. |
| `signal:Wait()` | Pauses the task until the next fire, and gives back what was fired. |
| `signal:Fire(...)` | Runs every connected function with these values. |
| `signal:FireDirect(...)` | The same, a little faster. The functions must not wait. |
| `signal:DisconnectAll()` | Disconnects every function. |
| `connection:Disconnect()` | Stops one function from being called again. |
| `connection.Connected` | `false` once the connection was disconnected. |

## Good to know

- A connected function runs as a task, so it may call `task.wait`. With `FireDirect` it may not.
- An error in one function does not stop the others. It goes to the log.

Every function is listed in the [signals reference](/docs/reference/tasks#waxsignal).
