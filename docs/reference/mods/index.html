Mods

What every mod has: mod, log, print, persist, storage, require and raw.

The Explorer searches everything on this page, and the classes of the game too.

mod

What a mod knows about itself. Every Lua file and folder of the mod is a field too: mod.Utils is Utils.lua and mod.extras.Utils is extras/Utils.lua. A file called id, name, version, dir, Reload, OnUnload or Content has to be required by its name instead.

Type name: WaxModInfo.

Open in the Explorer

MemberTypeDescription
idstringThe mod's folder name.
namestring
versionstring
dirstringPath of the mod's folder.
Reloadfun()Loads the mod again at the start of the next frame, as a saved file does.
ContentWaxContent?The game content the mod brings in content/<Id>.pak: models, textures, blueprints. Nil for a mod without that file.
OnUnloadfun(fn: fun(why: "reload"|"off"|"removed"|"failed"|"shutdown")): fun()Runs fn once when the mod is about to unload, before anything of the mod is taken away: its windows, tasks, connections and table changes are all still there. why is "reload" when the mod loads again straight after, "off" when the player switched it off, "removed" when its folder went, "failed" when the mod raised an error while it loaded, and "shutdown" when Wax itself stops. Several run newest first, and one that raises an error is logged and stops none of the others. fn must return at once: it cannot wait. Use it for what Wax cannot undo for you, such as a change made to the world. It does not run when the game closes or the map changes. Returns a function that takes fn off again.

require(name)

Loads a file of this mod and returns what it returned. require(mod.Utils) and require("Utils") are the same file, as are require(mod.extras.Utils) and require("extras.Utils"). A folder with an init.lua is loaded by the folder's name. require("@Id") gives another mod's exports.

ParameterType
namestring | WaxFile

Returns any

Blocked functions

These UE4SS functions raise an error when a mod calls them. The reason is given for each one.

FunctionNote
LoopAsyncBlocked in Wax mods: it runs Lua on another thread, which corrupts the game's Lua state. Use task.spawn or task.delay.
ExecuteAsyncBlocked in Wax mods: it runs Lua on another thread, which corrupts the game's Lua state. Use task.spawn or task.delay.
ExecuteWithDelayBlocked in Wax mods: it runs Lua on another thread, which corrupts the game's Lua state. Use task.spawn or task.delay.
RegisterKeyBindBlocked in Wax mods: it runs Lua on another thread, which corrupts the game's Lua state. Use ui.Hotkey.
RegisterKeyBindAsyncBlocked in Wax mods: it runs Lua on another thread, which corrupts the game's Lua state. Use ui.Hotkey.
RestartModBlocked in Wax mods: restarting a UE4SS mod destroys the Lua state Wax runs in. Reload the mod through Wax instead.
RestartCurrentModBlocked in Wax mods: restarting a UE4SS mod destroys the Lua state Wax runs in. Reload the mod through Wax instead.
UninstallModBlocked in Wax mods: it destroys the Lua state Wax runs in.
UninstallCurrentModBlocked in Wax mods: it destroys the Lua state Wax runs in.
