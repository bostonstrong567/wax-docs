Publish a mod

Put your mod in the catalogue, so other players can add it to their game from the Mods page.

The Mods page is the catalogue of Wax mods. This page says how your mod gets into it.

How publishing works

Your mod lives on GitHub

Put the mod in a public repository on GitHub. The catalogue reads it from there.

You submit the address

Press Submit a mod on the Mods page and give the address of the repository.

The mod is checked at once

The catalogue fetches the repository and checks it. You see the result on the same page.

A person looks at it

A mod that passed the checks waits for review. It is listed after a person has looked at it.

The version is signed

When the reviewer accepts a version, it is signed with Wax's key and listed. You sign nothing yourself.

Every new version goes the same way and is looked at again.

A mod is code that runs inside other people's games. So a person reads every version before players can add it.

The repository

One repository holds one mod. mod.lua and init.lua are at the top of the repository, not inside a folder.

  • The repository can have any name. The mod's id comes from mod.lua.
  • Lay out your other Lua files as you like. How a mod is built shows how one file loads another.
  • To publish two mods, make two repositories.
  • The whole repository, as GitHub packs it, can be at most 15 MB and 5,000 files and folders.
  • Two files cannot have names that differ only in capital letters, and a name Windows reserves, such as con.lua, is not taken. Links to other files are not taken either.

mod.lua

On your own PC mod.lua is optional. A published mod needs it. This one has every field:

FieldNeededWhat it is
idYesThe name the catalogue, the game and other mods know your mod by. Letters, digits and underscores only. It starts with a letter and is at most 64 characters long. It never changes.
nameYesThe name players see, on the Mods page and in the game.
versionYesThree numbers with dots between them, such as 1.2.0.
descriptionYesWhat the mod does, in at least 20 characters. The first line is the summary on the mod's card.
authorYesYour name, as the Mods page shows it.
categoryYesOne of the catalogue's categories. The Mods page lists them, and so does the view you submit from.
tagsYes1 to 10 short words that players can filter the list by.
homepageNoA web address with more about the mod. The mod's page links to it.
dependenciesNoIds of other mods that must load before this one. The mod's page tells players to install them too.
waxNoThe lowest Wax version the mod needs. The mod's page shows it as "Needs Wax 0.2.0".
keyWhen the mod has a windowThe key that shows and hides the mod's windows, such as "F6".
keysWhen the mod has a panel or other keysThe mod's other keys, one line each: "F10: Show or hide the pins".

mod.lua may only hold plain values like the ones above. It cannot call functions.

A key for a mod with an interface

A mod whose code calls ui.Window or ui.Panel must name a default key in mod.lua: key, or at least one line in keys. A mod with an interface and no key is refused, and the check says which file makes the window. The reason is the player: the key is on the mod's card before they switch the mod on, they can change it there, and Wax tells them when it is the same key as another mod's.

A mod that makes a window names the key that shows it, and a mod that makes a panel or has other keys names those:

  • Wax reads these before the mod runs, so the keys are on the mod's card of the Mods page while the mod is still switched off, and a clash with another mod's key is said before the player switches it on.
  • key is what ui.Window uses when you give it no key of its own.
  • A name in keys is the name you give ui.Bind: ui.Bind("Show or hide the pins", nil, fn) takes the key from mod.lua.
  • The player can change every one of them on the card. Their choice is kept.

The id

Pick the id once. Players get the mod as a folder with that name, other mods load it by that name, and saved settings are filed under it.

On your own PC the folder name is the id. So name your folder in Wax\mods\ the same as id. Then the mod you test is the mod players get.

The description

The first line is the summary. Keep it to one sentence that says what the mod does.

Leave an empty line after it, then write the rest: what the player sees, how to open it and which keys it uses. In mod.lua, \n starts a new line, so \n\n leaves an empty one.

What goes into the download

The catalogue makes a zip from the repository. Add to game and Download zip give players that zip. It holds one folder, named after the mod's id.

Everything in the repository goes into the zip, except:

  • the pictures folder
  • every file and folder whose name starts with a dot, such as .gitignore and .github
  • README.md, LICENSE, LICENSE.txt, LICENSE.md and CHANGELOG.md at the top of the repository
  • a docs folder at the top of the repository

A file of another type fails the check. Take it out of the repository.

Versions and tags

A version is one commit of your repository. Mark it with a git tag: the letter v and the version from mod.lua.

When you submit, you can name the tag or leave the field empty.

You submitThe catalogue takes
The tag v1.2.0The commit with that tag.
No tag, and the repository has releasesThe latest release. Its tag must be a version tag such as v1.2.0.
No tag, and no releasesThe newest commit of the default branch.

The rules:

  • A tag must match the version in mod.lua. The tag v1.2.0 goes with version = "1.2.0".
  • A version can be published once. You cannot replace 1.2.0 with other code.
  • A commit that is waiting for review cannot be submitted a second time.
  • At most 3 submissions of one repository can wait for review at a time.
  • The id belongs to the repository that first published it. No other repository can publish under that id.

Publish an update

  1. Change the mod.
  2. Raise version in mod.lua, for example from 1.2.0 to 1.2.1.
  3. Commit, tag the commit v1.2.1 and push.
  4. Submit the repository again.

The new version is checked and looked at like the first one. Until it is listed, players get the version that is listed now.

What the checks look for

The checks run as soon as you submit. Each one ends as a problem, a warning or a pass.

  • A problem stops the submission. Fix it in the repository and submit again.
  • A warning does not stop it. The reviewer sees it too.

This is what is checked:

CheckWhat it looks for
The layoutmod.lua and init.lua at the top of the repository.
mod.luaEvery field, by the rules in the table above.
A keyA mod that calls ui.Window or ui.Panel names a key in mod.lua.
The filesThe file types, the sizes and the number of files. The pictures, by the rules above.
The Lua codeEvery .lua file must compile. A file that does not is reported with its name and the line.
Calls that are refusedSee below.
Calls the reviewer looks atSee below.

Calls that are refused

These UE4SS functions break Wax or the game's Lua for every mod, not only for yours. A mod that calls one is not taken.

RefusedUse this instead
RegisterKeyBind, RegisterKeyBindAsyncui.Hotkey
LoopAsync, ExecuteAsync, ExecuteWithDelaytask.spawn, task.wait and task.delay
LoopInGameThreadAfterFramesA loop inside task.spawn with a task.wait in it. task.wait() with no number waits one frame.
RegisterBeginPlayPostHook, RegisterEndPlayPreHookFor creatures and players, the signals of game.Creatures and game.Players.
RestartMod, RestartCurrentMod, UninstallMod, UninstallCurrentMod, ClearAllDelayedActionsNothing. Wax reloads mods by itself.

Wax blocks most of these in the game as well. Functions that are blocked says why.

Calls the reviewer looks at

These are allowed. The checks point them out, and the reviewer reads closely what the mod does with them.

WhatFor example
Running programsos.execute, io.popen
Reading and writing files outside storageio.open, os.remove, os.rename
Loading code from textload, loadfile, dofile
The debug librarydebug.getinfo, debug.sethook
Raw engine accessraw, and what it gives you

A mod that needs one of them says so in its description, with the reason. Settings belong in storage, which needs none of these.

Review

A person reads the mod's code and its description, and looks at its pictures. This is done by hand, so there is no fixed time for it.

A mod is turned down when:

  • It does something its description does not tell the player.
  • It runs programs, fetches code or touches files, and the reviewer cannot see a good reason.
  • Its code is made hard to read on purpose, for example packed or encoded.
  • It harms other players, their saves or their PCs, or it breaks Wax or other mods.
  • It is another person's mod, published without their permission.
  • Its name, description or pictures mislead, or do not belong on a public page.

When a mod is not accepted, its status page shows a note from the reviewer. Fix what the note says and submit again. The version can stay the same, because it was never listed.

Signing

Accepting a version signs it. The reviewer's tool fetches the zip that was checked, works out its checksum itself and signs two things with Wax's key: the zip, and the list of the files in it. The key is on the reviewer's PC and never on the server.

  • The catalogue hands out a version only when it has both signatures.
  • A player's PC checks the signature before the mod is put in, and again before every update.
  • So players get the files that were read, and nothing else can be put in their place, not even by someone who took over the server.

What is signed has the key and the exact text that is signed.

Listed does not mean safe

A listed mod was read by a person once. That is not a promise that it is safe. It is also not a promise that it still works after the game is patched. ICARUS is patched often, and a patch can break a mod until its author updates it.

Limits

From one internet address, the catalogue takes 5 submissions an hour and 20 a day. A submission that fails the checks counts too. After that it asks you to wait.

Before you submit

  • Try the mod in the game. Copy the repository into Wax\mods\ as a folder named after the id and start the game. A new mod is listed switched off, so switch it on on the Mods page. Then use every part of it.
  • Look at the Log page of the Wax panel. It should show no errors from your mod.
  • mod.lua has every needed field, and version is one you have not published before.
  • The id is the one you want to keep.
  • The description says what the mod does and how to open it.
  • A mod with a window or a panel has key or keys in mod.lua.
  • The pictures are in pictures, in the right order, and within the limits.
  • The repository is public and holds nothing you do not want to share.
  • The commit has the tag v and the version, and the tag is pushed.

Submit

Open the Mods page and press Submit a mod. Paste the address of the repository:

Type the tag, or leave that field empty, and press Submit.

  • When there are problems, the page lists each one, with the file and the line where it has them. What you typed stays in the form.
  • When the mod passes, the page says it is waiting for review and gives you an address. Keep that address. It shows whether the mod was listed, and the reviewer's note when it was not.

Get mods

Find a mod on the Mods page and add it to your game with the button, or by hand.
